## 3.
### パターン1：最も基本（ローカルで新しくブランチを作って作業し、PRまたはマージするまで）

自分の手元で新しいブランチを切り、作業を完了させてマージするまでの標準的な流れです。

1. **最新のメインブランチに移動して最新状態にする**
```bash
git switch main
git pull origin main

```


2. **新しい作業用ブランチを作成して切り替える**（※初めての時もこれを使う）
```bash
git switch -c feature/new-function

```

3. **コードを修正・追加して、ステージング（add）する**
```bash
git add .

```


4. **コミットする**
```bash
git commit -m "新機能を追加"

```


5. **リモートリポジトリにブランチをプッシュする**（初回のみ `-u` オプションをつけると次回から `git push` だけ）
```bash
git push -u origin feature/new-function

```


6. **マージする**
* **チーム開発の場合:** GitHubなどのWeb画面で **Pull Request (PR)** を作成し、レビューを経てマージ
* **個人開発やローカルで直接マージする場合:**
```bash
git checkout main
git merge feature/new-function
git push origin main

```

### パターン2：すでにGitHub上に存在するブランチをローカルに持ってきて作業する時

チームメイトが作ったブランチや、別の端末で作ったブランチの続きを自分の手元（ローカル）で作業する場合

1. **リモートの最新情報を取得する**
```bash
git fetch origin

```


*Verification:* リモートの変更情報が手元に読み込まれる。
2. **リモートにある既存のブランチをローカルに切り替えてチェックアウトする**
```bash
git checkout feature/team-branch
# または git switch feature/team-branch

```


3. **コードを修正し、add・commit・pushする**
```bash
git add .
git commit -m "修正内容を記載"
git push origin feature/team-branch

```


4. **マージする**
* PRを作成して統合、またはローカルで `git checkout main` → `git merge feature/team-branch` を実行。



---

### パターン3：作業途中でメインブランチに新しい変更が入った時（コンフリクト対策・追従）

自分が作業している間に、他の人が `main` ブランチを更新した場合、自分のブランチを最新の `main` に合わせる（rebaseまたはmergeする）必要があり。

1. **作業中の変更を一時退避する（必要に応じて）**
```bash
git stash

```


2. **メインブランチに切り替えて最新化する**
```bash
git switch main
git pull origin main

```


3. **自分の作業ブランチに戻る**
```bash
git switch feature/new-function

```


4. **最新のメインの変更を自分のブランチに取り込む（マージ）**
```bash
git merge main

```


*(※退避していたものがある場合は `git stash pop` で戻します)*
5. **リモートへプッシュする**
```bash
git push origin feature/new-function

```
